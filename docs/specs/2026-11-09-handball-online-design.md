# スマホ向け ハンドボール対戦ゲーム 設計書

作成日: 2026-11-09

## 1. 目的（なぜ作るか）

友人とスマホでオンライン対戦し、**勝ったときの嬉しさ**を味わうためのゲーム。
勝敗は運ではなく、2人の操作の上手さ（パス回し・速攻・シュートの駆け引き）で決まること。

## 2. 決まっていること（ユーザーの決定）

- スマートフォンで遊ぶ。
- 友人と**オンラインで1対1**の対戦。
- 自分は**チーム全体**を操作する（操作中の1人を切り替えながら動かす）。
- 1試合は**約5分**。
- 操作感は **eFootball のイメージ**（仮想スティック＋アクションボタン、操作選手の自動／手動切替、それ以外の選手はAI）。
  ※ eFootball の名前・ロゴ・UIデザイン・アセットは使わない。操作方式の「ジャンル的な感触」だけを参考にする。
- 選手は**リアル寄りの見た目**：3Dの人型モデル（マネキン風）、走る・止まる・パス・シュートのアニメーション付き、チームごとにユニフォーム色を変える。中継風の視点。（ユーザー承認済み）
- 作り方は**全面的に任せる**。友人に**URLを送るだけで遊べる**こと。

## 3. 目標 / 非目標 / 失敗とみなすもの

**目標**
- URLを開く → 部屋を作る → コード/URLを友人に送る → 2人で5分の試合 → 勝敗表示、までが迷わずできる。
- スマホで快適に動く（目安：最近の iPhone / Android で 30fps 以上）。
- 操作が手に馴染み、上手い方が勝つ。

**非目標（今回はやらない）**
- 公式7人制ルールの完全再現（反則・2分間退場・7mスローの細部など）。
- アカウント、ランキング、マッチング（知らない人との対戦）。
- 3人以上の対戦、観戦モード。
- 実写レベルの顔・体型モデル。

**失敗とみなすもの（動いても失敗）**
- 通信のラグで操作がもたつき、勝っても負けても納得できない。
- 運（ランダム要素）で勝敗が決まる感じがする。
- 接続手順が面倒で友人が離脱する（アプリのインストール、アカウント登録が必要など）。
- スマホで重くてカクつく。

## 4. 作り方（Claude の判断）

- **形式**: スマホブラウザで動く Web ゲーム（インストール不要）。画面は**横持ち固定**（縦持ち時は「横にしてください」表示）。
- **3D描画**: Three.js。選手モデルは Three.js 公式サンプルの人型モデル（例: `Xbot.glb`、idle/walk/run アニメ付き）またはライセンス上問題のない同等の無料モデル。マテリアル色をチーム色に変更。パス・シュート動作のアニメが無い場合は、腕の簡易プロシージャルアニメ等で代用してよい（ビルダー判断）。
- **通信**: WebRTC の P2P 接続。シグナリングは PeerJS の無料公開サーバーを利用（サーバー運用不要）。
  - 部屋を作った側（ホスト）がゲームの正となるシミュレーションを実行。
  - ゲスト側は入力（スティック方向・ボタン）を毎フレーム送信。
  - ホストは状態（全選手・ボール・スコア・時間）を 20〜30Hz で送信、ゲスト側は補間して表示。
  - ゲストの体感ラグを減らすため、ゲストの操作選手は簡易予測（クライアント側予測）を入れてよい。
  - **ホスト有利について**（Claude の判断）: ホスト側が通信1往復分（4G で約50〜150ms）有利になることは受け入れる。重い同期方式（ロールバック等）は採用しない。公平にするため、「もう一度」で再戦するたびにホストとゲストを入れ替える。カット判定は少し猶予を持たせて、ゲスト側の不利を和らげる。
- **公開**（ユーザー決定）: **GitHub Pages** で静的サイトとして公開する。友人はURLを開くだけで遊べる（ログイン不要）。ユーザーが無料GitHubアカウントを作り、初期設定（数分）を行う。ビルド工程は不要な構成（素の HTML/JS、ライブラリは CDN）にして公開を簡単にする。
- **中継サーバー（TURN）**（ユーザー決定）: 最初は使わない（STUN のみ）。実際に友人とつながらなかった場合にだけ、無料TURNサービスへの登録をユーザーにお願いして追加する。後から設定を足しやすいよう、ICEサーバー設定は1か所にまとめておく。
- **一人で試せるモード**: 動作確認と練習用に「CPU対戦」モードも用意する（相手チームをAIが操作）。

## 5. ゲーム内容

### 5.1 コート・チーム
- ハンドボールコート（40m×20m 相当）。両端にゴールと 6m ゴールエリア（キーパー専用）、9m フリースローライン（点線）。
- 各チーム：コートプレーヤー6人＋ゴールキーパー1人。
- 自チームは青、相手は赤（ゲスト側画面では自分が青に見えるよう色・左右を入れ替えて表示してよい）。

### 5.2 操作（横持ち）
- **左下：移動スティック**（画面左半分のどこに触れてもそこを中心にスティックが出る方式でよい）。
- **右下：ボタン4つ**
  - 攻撃時: **パス**（スティック方向にいる味方へ）、**ロングパス**（前線の味方へ速攻パス）、**シュート**（長押しで強さ調整、離して発射。スティック方向で狙いを左右に）、**ダッシュ**（押している間加速、スタミナ消費あり）。
  - 守備時: **パス→選手切替**（ボールに最も近い選手へ）、**シュート→カット**（ボール保持者に寄せて奪いに行く）、ダッシュは同じ。
- 操作中の選手は足元の黄色い輪＋頭上の▼で表示。
- 攻撃時は自動でボール保持者に操作が移る。守備時はボールに最も近い選手へ自動切替（手動切替も可）。
- 操作画面のイメージ: `mockups/controls.png`

### 5.3 ルール（スマホ向けに簡略化）
- 試合時間 5:00（前後半なし、連続）。時間切れで得点の多い方の勝ち。
- 同点なら**延長（ゴールデンゴール、最大1分）**、それでも同点なら引き分け。
- ゴールエリア（6m）にはキーパー以外入れない。コートプレーヤーがエリアに入ろうとすると、エリアの線で止まる（ジャンプシュートでエリア上空に飛び込むのは可）。
- ボールがサイドラインを出たら、最寄りの相手選手のスローインで自動再開。ゴールラインを出たら、攻撃側が出した場合は相手キーパーのボールで再開。
- 得点後は相手チームのセンターからスローオフ。
- **ボール保持の制限**（Claude の判断）: ボールを持ってから 3 秒間は通常速度で自由に走れる。3 秒を過ぎると自動でドリブル扱いになり、移動速度が約15%落ち、カットされやすくなる（パス・シュートは可能）。遅攻より速攻・パス回しが有利になるようにするため。細かい歩数ルールは無し。
- **奪取**: カット成功は「保持者との距離・向き・タイミング」で決まる。ランダムは最小限（操作の上手さが勝敗を決めるため）。
- 反則・退場・7mスローは無し（非目標）。

### 5.4 AI（操作していない選手）
- 攻撃時: 適度に広がってパスコースを作る、速攻時は前に走る。
- 守備時: 6mライン手前でゾーン（6-0）を作り、ボールの方へ寄せる。
- キーパー: ボールとゴールの間に位置取り、シュートに反応（反応速度と届く範囲で止められるか決まる。強く・隅に打てば入りやすい）。
- **キーパーは常にAI**（Claude の判断）。プレイヤーはキーパーを操作しない。自動・手動の選手切替でもキーパーは対象外。キーパーがボールを持ったときだけ、パス操作でスローを出せる。

### 5.5 画面の流れ
1. タイトル: 「部屋を作る」「部屋に入る（コード入力）」「CPUと練習」
2. 部屋を作る → 4〜6文字のルームコードと共有URLを表示（URLを開けば自動参加）。「共有」ボタン（Web Share API）でLINE等に送れる。
3. 2人そろったらカウントダウンして試合開始。
4. 試合中: 上部にスコアと残り時間。ゴール時に短い演出（スロー再生や文字表示）。
5. 試合終了: **勝敗を大きく表示**（勝者の嬉しさが主目的なので演出を厚めに）。「もう一度」ボタンで同じ相手と再戦。
- 通信が切れたら「相手との接続が切れました」を表示してタイトルへ。

## 6. ビルダーに任せること
- ファイル構成、コード設計、物理（簡易でよい）の実装方法。
- 選手の速度・パス速度・シュート速度・キーパー能力などの数値調整（ただし「上手い方が勝つ」「5分で両チーム合計 10〜25 点程度」を目安）。
- 効果音・BGM の有無と内容（著作権のない素材または自作のみ）。
- カメラの細かい挙動。
- 3Dモデルの具体的な選定（ライセンス確認必須）。
